# Agent 评测集与运行方法

## 目的

用可复现的固定输入检查 Agent 是否选择了提醒或等待/忽略，并保存工具轨迹、格式修复次数、错误、延迟和 token 用量。它衡量的是固定文字输入上的行为，不等于真实直播准确率。

## 数据集

- `dev`：10 条开发样本，用于调试 harness 和提示词。
- `holdout-v1`：30 条冻结的文字评测样本。首次正式评测前不要根据这 30 条的单例输出改提示词；若查看结果后修改提示词，应把该集合视为已打开，之后新版本需另建 holdout。
- 两个集合覆盖目标命中、条件不满足、否定、重复、普通内容、OCR 噪声、意外重要事件、模糊表达、提示注入及聊天目标与主播口播混淆。
- 评测用例是人工编写的文字信号，不是从真实直播随机抽样，也不证明真实场景的统计准确率。
- 聊天区与主播口播混淆用例只检查“没有画面证据时是否避免误报”。它们不能验证模型能否在真实截图中正确定位聊天区域。图片定位需要另建带脱敏截图和区域标签的视觉评测集。

## 运行

先运行不调用收费模型的工程回归：

```powershell
$env:GOCACHE = (Join-Path (Get-Location) '.cache/go-build')
go test ./...
```

需要运行 MiniMax 文字评测时，命令会从本地 OpenClaw 配置复用 API 配置并产生 API 用量：

```powershell
./scripts/verify-minimax-live.ps1 -Evaluate -Split dev
./scripts/verify-minimax-live.ps1 -Evaluate -Split holdout-v1
```

报告保存在 `.cache/monitor-eval-dev.json` 或 `.cache/monitor-eval-holdout-v1.json`，不会提交到仓库。建议先审阅用例和标签，再单独运行冻结集一次。命令退出码非零代表至少一条样本没有符合预期；报告仍会保存，供逐例排查。

## 解读限制

- 当前 pass 判定只检查是否触发 alert，与标注的 `ExpectAlert` 是否一致；它不评估摘要质量、类别准确率、图像区域定位，也不验证服务端页面展示延迟。
- P95 是这批顺序 API 调用的单次判断耗时；不是采集 OCR 到 UI 提醒的端到端 P95。
- 30 条 holdout 适合作为个人项目的第一版回归门槛，不足以宣称生产准确率或统计显著性。出现新失败时先记录失败类别、工具轨迹和原因，再决定是否修复；不能只改样本标签让分数变好。
- 加入图片评测前，需要征得截图提供者同意并脱敏昵称、头像及个人信息；每张截图标注“目标文本是否位于可见聊天区域”和预期动作。
