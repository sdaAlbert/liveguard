# LiveGuard 第一阶段交付报告

**日期**：2026-09-14
**阶段目标**：建立以真实抖音公开页面为首个目标的 Go 浏览器巡检 Agent 基础框架，并完成本地可重复闭环。

## 1. 阶段结论

第一阶段骨架已经可编译、可启动、可创建任务、可持久化、可调用 Chrome、可保存截图、可生成结构化报告，并能在浏览器或模型发生故障时明确失败或降级。

真实抖音首页已经完成一次只读访问。Chrome 成功加载页面并返回标题 `验证码中间页` 与截图，证明真实站点链路可以到达，同时也证明真实网站会触发访问验证。第一次规则把该页面错误归类为未阻塞；分类器已经修复为同时检查标题和正文，并增加了回归测试。

OpenAI Planner 的代码已经完成，但当前开发机无法连接 `api.openai.com`。运行时会记录模型错误并自动使用确定性计划完成任务，因此本阶段不能宣称模型在线规划已经验证成功。

## 2. 已交付能力

### Control Plane

- 创建、查询和取消巡检任务的 HTTP API。
- 使用 SSE 推送任务事件。
- 工业指挥台风格的本地控制页面。
- 任务队列、运行状态、事件时间线、截图和检查报告展示。

### Agent Runtime

- `Planner` 接口隔离模型供应商。
- OpenAI Responses API Planner。
- 2-6 个检查项的计划预算。
- 白名单检查类型和结构校验。
- 模型失败后的确定性降级。

### Browser Runner

- 只允许 HTTP/HTTPS URL。
- 精确域名边界，拒绝 `douyin.com.evil.example` 一类伪装地址。
- 使用独立 Chrome Profile。
- Chrome DOM 导出、标题解析和 PNG 截图。
- 25 秒浏览器工具 deadline。
- 75 秒任务总预算。
- 登录或验证码分类为 `needs_human`。

### 状态和证据

- Append-only JSONL 任务快照。
- 启动时将遗留的 `planning`、`running` 任务恢复到队列。
- 每次状态变化都有时间戳事件。
- 报告状态区分 `passed`、`failed`、`unverified` 和 `needs_human`。
- 所有检查项关联同一次页面截图。

## 4. 验证结果

最终执行：

```text
go vet ./...       PASS
go test ./...      PASS
go build           PASS
```

覆盖的关键回归测试：

- 域名白名单不能被后缀伪装绕过。
- 验证页面进入人工介入状态，而不是普通失败。
- 页面标题中的验证码提示可以被识别。
- DOM 中的脚本和样式不会进入可见文本证据。
- 中断任务在 Store 重新打开后回到队列并留下恢复事件。
- Store 返回副本，调用者不能绕过更新接口修改状态。
- 确定性计划符合与模型计划相同的能力白名单。
- 未知工具能力会被拒绝。

## 5. 本阶段发现的问题

| 问题 | 系统行为 | 处理结果 |
|---|---|---|
| Go 默认缓存目录不可写 | 编译失败 | 缓存迁移到项目 `.cache` |
| 无法下载 chromedp | 依赖安装失败 | 第一版使用零依赖 Chrome CLI，保留 Runner 接口 |
| 受限环境无法启动 Chrome IPC | 浏览器任务在预算内失败 | 本地浏览器集成使用获批运行环境 |
| CSP 阻止演示页内联样式 | 截图无样式 | 样式迁移到同源静态文件 |
| SSE 导致 DOM 导出不退出 | 浏览器长时间运行 | 增加工具 deadline 和截图模式 |
| 验证码只出现在标题 | 误报为未阻塞 | 标题与正文共同分类，增加回归测试 |
| OpenAI API 当前不可达 | 模型规划失败 | 记录原因并降级，在线规划待验证 |
| Codex Browser Use 当前不可连接 | 无法交互式点击控制台 | 使用项目 Chrome Runner 完成视觉截图 |

## 6. 当前架构边界

本阶段是本机 MVP，不是生产级 Sandbox：

- 独立 Chrome Profile 提供会话隔离，但不等于容器或虚拟机安全隔离。
- 初始 URL 有域名白名单，但页面重定向和子资源还没有网络策略层控制。
- JSONL Store 适合单进程演示，不适合多实例并发写入。
- Chrome CLI 可以加载、导出和截图，尚不能展示逐步点击轨迹。
- Agent 当前负责检查计划，执行层由确定性代码控制。

这些限制已经进入 `PROJECT.md`，不会在简历或面试中包装成未实现的能力。

## 7. 下一阶段建议

下一阶段优先级如下：

1. 接入可用的 CDP 客户端，实现导航、查找、点击、截图等真实工具调用。
2. 将检查项保存为独立 checkpoint，Worker 重启后从未完成项恢复。
3. 增加暂停、人工接管和继续执行接口。
4. 添加一个包含正常页、验证码页、元素缺失页和慢页面的评测集。
5. 网络恢复后验证 OpenAI Planner，并记录 Token、延迟和计划合法率。
6. 完成以上闭环后，再加入 PostgreSQL、Redis Streams 和 gRPC Runner。
