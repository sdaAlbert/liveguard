# 阶段二真实数据验收手册

目标：把代码模拟测试和真实抖音浏览器验收分开记录。浏览器需要用户亲自登录/授权；测试不需要提供账号密码、Cookie 或 API Key。

## 你需要准备的真实素材

1. 一个你能正常打开的抖音直播间 URL，建议挑正在直播且页面有字幕/文字叠层的房间，连续测试 20 分钟。
2. 两条监控目标：
   - 文字目标，例如“主播正式公布新品或发布时间时提醒我”。
   - 需要画面确认的目标，例如“主播口播提到福袋开始后，检查画面里是否真的出现福袋入口或倒计时，出现才提醒我”。
3. 测试时观察到的内容及大致时间：实际出现的字幕/口播、是否应该提醒、是否真的提醒、提醒延迟。
4. 用户主动选择 Chrome 标签页并分享音频的权限。音频实验必须实际听到直播标签声音；静音或无音轨不能验证 ASR。

没有发生目标事件也有价值：记为“本次直播没有出现正样本”，不要用另一个合成事件冒充真实命中。

## A. 不开浏览器的代码回归（不产生模型 API 费用）

在仓库根目录运行：

```powershell
go test ./...
go vet ./...
go build ./...
```

这是 mock/单测验收，不验证抖音登录、Chrome 音频共享或真实 MiniMax 识别。当前 Windows 的 `go test -race` 还受本机 C 编译器限制。

## B. MiniMax / ASR 单独冒烟（会消耗 API 额度）

```powershell
.\scripts\verify-minimax-live.ps1
```

该脚本用 Windows 中文语音合成生成一段本地测试音频，调用真实 MiniMax ASR；还会用合成测试图调用 M3 看图工具。它能区分“供应商 API 和格式可用”与“真实 Chrome 音频分享可用”，**不代表抖音端到端验收**。如果只想跑固定文字评测：

```powershell
.\scripts\verify-minimax-live.ps1 -Evaluate
```

这同样调用真实 M3，也会消耗额度。开始前确认 MiniMax 配置可用；启动脚本不会显示密钥。

## C. 真实抖音 OCR 闭环

1. 运行 `powershell -ExecutionPolicy Bypass -File .\scripts\run-mvp.ps1`，打开 <http://127.0.0.1:8080>。Docker/PostgreSQL 不是这个本地 MVP 的必需项。
2. 点“打开抖音登录窗口”，在专用 Chrome 窗口中手动登录。不要把密码、验证码或 Cookie 发给 LiveGuard/我。
3. 回监控室粘贴直播间的**完整 URL**，输入文字目标，点“开始自动监控”。确认卡片显示的 URL/直播间与预期一致。
4. 观察至少 20 分钟。检查页面最新 OCR 信号、实际抓帧间隔、抓帧耗时、事件证据和提醒；记下出现字幕的实际时间及提醒显示时间。
5. 人工检查三类片段：普通闲聊不应频繁提醒；明确满足目标时应该提醒；否定/取消/推测性措辞不应误报。直播内容不可控时，只记录实际发生的类别，不要假造测试结果。

验收点：OCR 文字来自当前直播页面；地址没有串到别的房间；信号有观察/接收时间；Agent 决策能看到证据和工具轨迹；重复内容不会重复打扰。

## D. 真实直播音轨 ASR

1. 先完成上面的 B（排除 MiniMax ASR API 本身不可用），再启动服务并创建一条 C 中的真实浏览器监控。
2. 在该监控卡片点“开启口播识别”。在 Chrome 系统选择器中选正在播放抖音直播的标签，并勾选“共享标签页音频”。不同 Chrome 版本的文案可能略有差异。
3. 等至少两个约 6 秒录音片段处理完成。页面应出现 `ASR` 信号和转写文本；确认内容能对应主播刚说的话，而非合成样本或其他标签声音。每段转写还会触发 Agent 判断，因此片段处理和端到端提醒不保证在 6 秒内完成。
4. 记录每条 ASR 信号的 `observed_at`、页面接收时间、转写是否正确和信号到达延迟。结束时点“停止口播识别”，确认浏览器停止采集。

若选择器没有音频选项、页面静音或选错标签，该次不能算 ASR 成功；先确认直播在播放且有声音，再重新授权。该功能按用户选择录制的标签音轨，不读取未授权的系统音频。

## E. 验证 ASR 触发同窗口看图

创建一条明确依赖画面的目标，例如：

```text
主播口播提到福袋开始后，检查当前画面里是否真的出现福袋入口或倒计时；确认出现才提醒我
```

开启该监控的口播识别。遇到对应口播后，在卡片调查记录里找 `inspect_live_frame` 工具和 `m3_vision` 证据；确认画面内容属于这条监控当前打开的直播间。命中提醒必须同时保留 ASR 原文和视觉结论。

自然直播不一定刚好发生对应事件。如果 20 分钟内没遇到，记录“未触发，不能验收此分支”。可在同一个专用 Chrome 标签中播放你有权使用的可控回放，验证工具分支，但报告必须标成“Chrome 回放”，不能说成“真实抖音直播通过”。抓帧失败时应看到工具失败，不能生成编造的画面证据。

## F. 停止、取消和延迟

- 在 ASR 正在录制时点停止：确认录制轨道关闭。
- 在一次慢模型判断进行时点停止：确认监控变成已停止，之后不新增提醒。
- 长时间运行时看“最近实际采样间隔”，不把计划间隔当作实际间隔。音频是串行处理：当前音频片段完成 ASR/Agent 请求后才开始下一段，因此高延迟时可能有采集空档；这轮不承诺每句话都必达。

## G. OCR 去重与聊天区目标提醒

1. 观察卡片的 OCR 信号：稳定字幕/固定页面文字在 2 分钟内只应作为一次新增信号进入 Agent；同画面出现新的聊天行或字幕行时，应只把新增内容送去判断。
2. 把目标设成一个聊天里可能出现的明确内容，例如“有人在评论区问新地图什么时候上线时提醒我”。OCR 命中后 Agent 应查看当前画面确认文字属于聊天区，再发提醒；无关聊天和仅由主播口播提到该词不应误报。此确认会产生额外视觉模型用量。
3. 再设一个主播活动目标，例如“主播宣布抽奖开始时提醒我”，检查活动命中和聊天命中都只发提醒，不生成回复草稿，也不自动发送消息。
4. 对真实直播没有出现的正样本记为“未遇到”，可另用有权使用的回放画面验证交互，但需标注为回放。

## 记录模板

```text
日期/时区：
测试类型：真实抖音 / 同一 Chrome 标签回放 / API 冒烟
直播 URL（可打码房间号）：
监控目标：
运行起止时间：
Chrome 登录与最终打开 URL 是否正确：
OCR：字幕样例、观察时间、识别正确/错误
ASR：是否分享了正确标签音轨、转写样例、观察时间
看图：是否调用 inspect_live_frame、m3_vision 是否对应当前直播间
提醒：提醒/未提醒、理由、最新证据到提醒耗时
负例：普通/否定内容是否误报
停止：停止后有无新增提醒
实际采样间隔/抓帧耗时：
失败与复现步骤：
```

分享测试结果时只发上述脱敏记录和页面可见错误；不要贴 API Key、账号密码、Cookie、验证码或带个人信息的截图。
